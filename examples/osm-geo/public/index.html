          PulseMesh

          Live traffic, no traffic server

          Off

          Peers gossip 42-byte anonymous observations. Every subscriber recomputes the same weighted-median aggregate, and the router consumes it through the ordinary live-traffic contract — so with no peers, no data, or no mesh at all, the route still works.

          Report what you can see

          A report is public and carries the spot you are at. It becomes a fact on the map only when other peers corroborate it.

            Share this drive

            The whole capability is 45 bytes in the URL fragment, which browsers never transmit — no server, here or anywhere, sees a tracking key.

            This device

            A job is encrypted to the device it is for, so a device must be enrolled before it can be sent one. This is this browser's card: show it to a dispatcher to be given jobs.

            Enrolled devices

            Read the fingerprint aloud and check it matches the one on the other phone — a card is bytes on a screen, and a screen in a depot can be showing anybody's.

              This fleet's seed

              A follow link and a job are keys, not addresses: a phone that has never met the mesh has nothing to dial. Run pulsemesh_keeper.mjs --seed-card and scan or paste the wayfind://seed#… it prints. The address then travels inside the sealed job, so it reaches the driver's device and nobody else — it is deliberately never in an offer, which is broadcast to strangers.

              Dispatch a job

              A ticket carries the run's own key, so the customer's link can be printed on the order confirmation before a courier has been found — and if the bike breaks, the same ticket goes to the next enrolled device and that link keeps working. The mode chosen above travels in the ticket: whoever decides who gets the link decides what the link is worth. The ticket itself is never in the clear — it is sealed to the driver's device and to this one, so this dispatcher can still open it.
